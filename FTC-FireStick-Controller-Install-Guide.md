The controller opens scoring displays and monitors them from a Mac; each television continues displaying its page independently.</p><nav><a href="#s1">1 Device inventory</a><a href="#s2">2 Power and network</a><a href="#s3">3 Nest reservations</a><a href="#s4">4 Fire Stick settings</a><a href="#s5">5 Mac tools</a><a href="#s6">6 Connection testing</a><a href="#s7">7 Controller operation</a><a href="#s8">8 Command sequences</a><a href="#s9">9 Troubleshooting</a><a href="#s10">10 Final script</a><a href="#s11">11 Sources</a></nav><section id="s1"><h2>1 Device inventory and physical labels</h2><p>Use one fixed address per stick. The controller selects its menu sequence by IP address; changing an address without updating the controller can select the wrong sequence.</p><table><thead><tr><th>Device label</th><th>IP address</th><th>Model</th><th>Menu sequence</th><th>MAC address to record</th></tr></thead><tbody><tr><td>FTC-100</td><td>192.168.86.100</td><td>E9L29Y</td><td>E9</td><td>_________________</td></tr><tr><td>FTC-101</td><td>192.168.86.101</td><td>E9L29Y</td><td>E9</td><td>_________________</td></tr><tr><td>FTC-102</td><td>192.168.86.102</td><td>E9L29Y</td><td>E9</td><td>_________________</td></tr><tr><td>FTC-103</td><td>192.168.86.103</td><td>E9L29Y</td><td>E9</td><td>_________________</td></tr><tr><td>FTC-104</td><td>192.168.86.104</td><td>E9L29Y</td><td>E9</td><td>_________________</td></tr><tr><td>FTC-105</td><td>192.168.86.105</td><td>K2R2TE</td><td>K2</td><td>_________________</td></tr><tr><td>FTC-106</td><td>192.168.86.106</td><td>M3N6RA</td><td>E9</td><td>_________________</td></tr></tbody></table><p>E9L29Y is the 2018 Fire TV Stick 4K; K2R2TE is the 2021 Fire TV Stick 4K Max; M3N6RA is the 2023 Fire TV Stick 4K. The M3 has been confirmed by the user to work with the E9 hiding sequence. If using Ethernet, record the Ethernet adapter MAC as well and reserve the address for the interface actually in use. Repeat the short device ID on the HDMI extender and power lead. Label any Ethernet adapter as belonging to the same device. Add its location when assigned, for example “FTC-102 — Main gym ranking.” Keep the full inventory with the event equipment.</p><pre><code>FTC-106   M3N6RA

Do not copy a MAC from another stick or infer it from the model number.</p></section><section id="s2"><h2>2 Power and network preparation</h2><ol><li>Connect the scoring server, control Mac, and display sticks to the same event LAN. This configuration uses <strong>192.168.86.0/24</strong>, with the display server at <strong>192.168.86.37</strong>.</li><li>Open the scoring page on the Mac first. Confirm that the server is running, listening on its LAN interface, and allowed through its firewall. A different LAN or server IP requires changes to the controller.</li><li>Power each stick from a reliable wall adapter and cable. Avoid assuming a TV USB port supplies enough power. A boot loop should first be tested with known-good power and no OTG accessories.</li><li>Use Ethernet adapters where practical. For PoE, use an appropriate active PoE splitter supplying the correct regulated USB voltage and enough current; the stick itself is not a native PoE device. Test the complete power and Ethernet chain before event day.</li><li>Keep display traffic separate from spectator guest access where possible. Guest isolation can prevent ADB and access to the local scoring server.</li></ol><p>A reserve address is only useful if the device can reach the correct LAN. At the tournament, verify the server and each reservation rather than assuming a setup tested at home will transfer unchanged.</p></section><section id="s3"><h2>3 Reserve the seven IP addresses in Nest</h2><p>Use Google Home → Wi-Fi → Settings → Advanced networking → DHCP IP reservations. Select the correct device, assign the address in the inventory, and save. Menu wording may differ with app versions. Match the MAC address, not only the friendly device name. <a href="https://support.google.com/googlehome/answer/6274660">Google reservation instructions</a>.</p><ol><li>Leave the Fire Stick on Automatic or DHCP IP configuration.</li><li>Remove a previous reservation if moving an address from an old stick to a new one. Keep the old stick disconnected during the transfer.</li><li>Create the new reservation using the current stick’s actual interface MAC. Check that no other device is manually assigned the same address.</li><li>Reconnect or power-cycle the stick and verify its address on the Network screen.</li></ol><p><strong>Previously observed issue:</strong> a stick continued receiving .157 after .100 had been reassigned from another stick. Resets and forgetting the network did not resolve it during this conversation. Do not assume that problem is fixed. Verify the reservation and device MAC; temporarily reserving an unused address can distinguish a problem with reusing .100 from a reservation that is not being applied. The current controller only accepts .100–.106.</p></section><section id="s4"><h2>4 Fire Stick setup with the remote</h2><ol><li>Complete the normal Amazon setup and registration. Connect to the event network and finish planned updates before final testing.</li><li>Install or open <strong>Amazon Silk</strong>, sometimes shown as <strong>Internet</strong>. Complete first-run prompts. Open the scoring page manually once to check access.</li><li>Go to <strong>Settings → My Fire TV → About</strong>. Highlight the device-name entry and press the remote’s center Select button <strong>seven times</strong> to reveal Developer Options if hidden.</li><li>Go back to <strong>Developer Options</strong> and set <strong>ADB debugging → On</strong>. The controller does not require enabling installation of unknown apps.</li><li>When the Mac first connects, approve the <strong>Allow debugging</strong> prompt on the TV. Select <strong>Always allow from this computer</strong> if offered, then Allow. This approval cannot be completed by the controller before the Mac is authorized.</li><li>In <strong>Preferences → Featured Content</strong>, turn <strong>Allow Video Autoplay</strong> and <strong>Allow Audio Autoplay</strong> off. This reduces moving and audible ads; static Home ads remain.</li><li>In <strong>Preferences → Notification Settings</strong>, set <strong>Do Not Interrupt → On</strong>. It may not suppress every system dialog.</li><li>For controlled event preparation, use <strong>Applications → Appstore → Automatic Updates → Off</strong> if you want to manage app updates manually. Turning this off can still leave update prompts when apps open. Apply necessary updates between events.</li><li>Turn off the TV or monitor’s own sleep timer and automatic power-off features. Fire Stick settings do not control all display power settings.</li></ol><p>Amazon documents ADB setup and authorization at <a href="https://developer.amazon.com/docs/fire-tv/connecting-adb-to-device.html">Connect to Fire TV through ADB</a>. After a factory reset or a change of Mac, repeat the authorization step.</p></section><section id="s5"><h2>5 Install the tools on a modern Mac</h2><p>Use a supported macOS version. Install Homebrew from <a href="https://brew.sh">brew.sh</a> and follow its displayed shell configuration instructions. macOS may request Apple Command Line Tools during installation. Then open a new Terminal window and run:</p><pre><code>brew install python scrcpy
brew install --cask android-platform-tools
python3 --version
adb version
scrcpy --version
command -v python3
command -v adb
command -v scrcpy</code></pre><p>Python runs the controller’s local server; ADB connects and sends commands; scrcpy provides optional continuous video and keyboard or mouse control. Chrome, Safari, or another supported browser shows the controller page. Android Studio and extra Python packages are not needed for this controller. <a href="https://github.com/Genymobile/scrcpy/blob/master/doc/macos.md">Official scrcpy Mac installation instructions</a>.</p><p><strong>Existing Mac:</strong> the delivered controller defaults to ADB at <code>~/Downloads/platform-tools/adb</code> and the known working launcher <code>/Users/ahot/scrcpy-2.7/run x</code>. If those files already work, keep using them. The following compatibility launcher lets a modern Homebrew installation use the same controller without compiling scrcpy.</p><p>Create a dedicated folder and a launcher named <code>run</code>. It discards the legacy build-directory argument <code>x</code>, translates the bitrate option, and uses the installed scrcpy binary.</p><pre><code>mkdir -p &quot;$HOME/FTC-FireStick/scrcpy-launcher&quot;
cat &gt; &quot;$HOME/FTC-FireStick/scrcpy-launcher/run&quot; &lt;&lt;&#x27;SH&#x27;
#!/bin/bash
[ &quot;${1:-}&quot; = x ] &amp;&amp; shift
args=()
while [ &quot;$#&quot; -gt 0 ]; do
  if [ &quot;$1&quot; = -b ]; then
    shift
    args+=(&quot;--video-bit-rate=${1:?Missing bitrate}&quot;)
  else
    args+=(&quot;$1&quot;)
  fi
  shift
done
for binary in /opt/homebrew/bin/scrcpy /usr/local/bin/scrcpy; do
  if [ -x &quot;$binary&quot; ]; then
    exec &quot;$binary&quot; --no-audio &quot;${args[@]}&quot;
  fi
done
echo &quot;scrcpy not found in the standard Homebrew locations.&quot;
exit 1
SH
chmod +x &quot;$HOME/FTC-FireStick/scrcpy-launcher/run&quot;</code></pre><p>The wrapper disables scrcpy audio so monitoring multiple screens does not create duplicate audio on the Mac. It does not mute the televisions.</p><p>Save the controller in <code>~/FTC-FireStick</code>. On a modern Mac using this wrapper, add these lines <strong>immediately below its first line</strong> (<code>#!/bin/bash</code>):</p><pre><code>export PATH=&quot;/opt/homebrew/bin:/usr/local/bin:$PATH&quot;
export FTC_ADB=&quot;$(command -v adb)&quot;
export FTC_SCRCPY_DIR=&quot;$HOME/FTC-FireStick/scrcpy-launcher&quot;</code></pre><p>Placing these exports inside the .command file makes them apply when double-clicking it; exporting them in an unrelated Terminal session may not affect a Finder launch. If your tools are installed elsewhere, use their actual paths.</p><pre><code>chmod +x &quot;$HOME/FTC-FireStick/FTC-FireStick-Controller.command&quot;</code></pre><p>If macOS blocks the file, use its normal Open or Privacy and Security approval flow for this reviewed file. Do not disable Gatekeeper globally.</p></section><section id="s6"><h2>6 Authorize and test each connection</h2><p>With the stick’s screen visible, connect from Terminal. Substitute each reserved address and approve the on-screen debugging prompt:</p><pre><code>adb connect 192.168.86.100:5555
adb devices
adb -s 192.168.86.100:5555 get-state</code></pre><p>The state should be <code>device</code>, not <code>unauthorized</code> or <code>offline</code>. Repeat for .101 through .106. On macOS, allow local network access for Terminal or the browser if a prompt appears.</p><p>Test mirroring with Homebrew scrcpy:</p><pre><code>scrcpy -s 192.168.86.100:5555   --window-title &quot;192.168.86.100 - E9L29Y&quot;   --max-size=800 --max-fps=15 --video-bit-rate=1M --no-audio</code></pre><p>Or use the existing setup:</p><pre><code>cd /Users/ahot/scrcpy-2.7
./run x -s 192.168.86.100:5555   --window-title &quot;192.168.86.100 - E9L29Y&quot;   --max-size=800 --max-fps=15 -b 1M</code></pre><p>Keep one ADB installation in use where possible; the controller exports its selected ADB path to scrcpy. Current firmware can affect remote-control capabilities, so test ADB commands and mirroring on every stick after updates.</p></section><section id="s7"><h2>7 Use the controller page</h2><ol><li>Double-click <strong>FTC-FireStick-Controller.command</strong>. Keep its Terminal window open. The controller opens a browser page served only on the Mac’s loopback address, using an access token.</li><li>On a fresh page, all seven cards are visible and automatically run setup with event <strong>s0</strong> and display type <strong>Audience</strong>. This wakes devices and can interrupt anything they were showing. Start the controller during preparation, not unexpectedly during a match.</li><li>Use the <strong>−</strong> button to minimize unused cards. The remaining cards reflow; restore devices using the compact tray. Hidden cards stop requesting previews and are excluded from group actions. Minimizing does not power off a stick, close an existing scrcpy window, or cancel setup already in progress.</li><li>Enter the server origin, for example <strong>http://192.168.86.37</strong>, and the event code. Choose a display type from the list below. The page shows the resulting URL.</li><li>Press <strong>Set up display</strong> on an individual card, or <strong>Set up visible</strong> to apply the current selection to every visible card. To assign different roles, choose a role, set up its individual device, then change the role and set up the next one.</li><li>Read each card’s status and expand <strong>Activity log</strong> for settings warnings or errors. “Ready — check preview” means commands finished; visually verify the correct event, display, and hidden toolbar.</li></ol><table><thead><tr><th>Display choice</th><th>Exact query value</th></tr></thead><tbody><tr><td>Audience</td><td>audience</td></tr><tr><td>Field</td><td>field</td></tr><tr><td>Pit</td><td>pit</td></tr><tr><td>Sponsor</td><td>sponsor</td></tr><tr><td>Championship bar</td><td>cmpBar</td></tr></tbody></table><pre><code>http://192.168.86.37/event/s0/display/?type=audience</code></pre><p><strong>Refresh controls:</strong> live previews are checked by default and refresh every <strong>2 seconds</strong>. Choose Realtime, 2 seconds, 5 seconds, or 10 seconds. Realtime requests the next screenshot as soon as the previous request completes; it is not a continuous video stream. Actual refresh speed depends on the stick, network, and screenshot capture time. Use 5 or 10 seconds to reduce monitoring load. Turn off Live previews to pause automatic capture; Refresh previews performs a manual refresh of visible cards.</p><p><strong>scrcpy controls:</strong> Open scrcpy during setup is unchecked by default. Open scrcpy on one card, or Open visible scrcpy for all visible devices. Windows are titled with IP and model. The requested limit is <strong>800 pixels on the longest dimension, 15 FPS, 1 Mbps</strong>—approximately 800 × 450 on a 16:9 display. This changes the monitoring video, not the TV output resolution. Close unneeded scrcpy windows yourself.</p><p><strong>Remote controls:</strong> Wake, Home, Back, Menu, arrows, and OK send keys to the selected stick. Home leaves the scoring display. Reconnect visible or a card’s Reconnect retries ADB; reconnecting alone does not run display setup. Setup and remote controls are disabled for that card while its action is busy, but Minimize remains available.</p><p>To stop the controller, press Control-C in Terminal. Merely closing the browser tab does not stop the local server. The scoring pages run on the sticks independently of the controller.</p><p>The server chooses a new local port when launched. Minimized-card preferences may survive a page reload, but should not be relied on across controller restarts. The current page does not persist per-device event or display assignments and is not accessible from another computer.</p></section><section id="s8"><h2>8 Commands and confirmed menu sequences</h2><p>Each setup connects through ADB, applies the settings below, wakes the device, presses Home, waits two seconds, and opens the selected URL in <code>com.amazon.cloud9</code>. It reads settings back and reports unexpected values.</p><pre><code>adb -s 192.168.86.100:5555 shell settings put secure screensaver_enabled 0
adb -s 192.168.86.100:5555 shell settings put secure sleep_timeout 0
adb -s 192.168.86.100:5555 shell settings put system screen_off_timeout 2147483647</code></pre><p>The screen-off value is roughly 24.9 days, not infinite. A successful readback does not prove Fire OS will honor every idle setting. The TV’s own timers remain separate.</p><table><thead><tr><th>Model</th><th>Sequence after opening the page</th><th>Evidence</th></tr></thead><tbody><tr><td>E9L29Y</td><td>Wait 5s → MENU → wait 5s → MENU</td><td>Established E9 scheme</td></tr><tr><td>K2R2TE</td><td>Wait 2s → MENU → DOWN ×5 → wait 2s → MENU → wait 2s → MENU</td><td>Confirmed working by user</td></tr><tr><td>M3N6RA</td><td>Wait 5s → MENU → wait 5s → MENU</td><td>Confirmed working by user with E9 scheme</td></tr></tbody></table><p>The five K2 DOWN presses have a 0.15-second pause between them. ADB waits for the app activity launch, not for the webpage to finish rendering; all page waits are timed. The previously tried DOWN-only sequence scrolled the page without hiding the toolbar, so it is not used.</p><p>This controller is Mac-initiated. It does not install a service on the Fire Sticks or launch the browser automatically after a cold boot. The Home screen may appear briefly because setup deliberately presses Home before launching Silk.</p></section><section id="s9"><h2>9 Event recommendations and troubleshooting</h2><p><strong>Before the event:</strong> reserve addresses, label equipment, authorize ADB, test each required display role, test after updates, and run a long idle test. Keep a remote and known-good spare power supply available. Choose a sensible preview rate rather than running all screens and all scrcpy windows continuously if monitoring is unnecessary.</p><p><strong>Updates and popups:</strong> there is no verified universal ADB command here to disable Home autoplay or Fire OS updates. Use the Fire Stick menus for autoplay and notifications. For local scoring-only sticks, blocking internet access while retaining local LAN access can prevent new online update downloads, but must be tested with the event router. Do not assume Google Home Pause preserves LAN access. Already-downloaded updates or dialogs can still appear. A stick showing YouTube needs internet access.</p><p><strong>YouTube:</strong> all three models can be used to watch the same livestream. Prefer the official YouTube app for a dedicated stream display, and test embedded playback separately. Multiple sticks buffer independently and may show slightly different times. Use one audio source for nearby spectator screens to avoid echo. The controller’s display setup opens the scoring page; it is not a YouTube channel-selection tool.</p><table><thead><tr><th>Symptom</th><th>Action</th></tr></thead><tbody><tr><td>Unauthorized</td><td>Approve the debugging prompt on that stick using its remote; then reconnect.</td></tr><tr><td>Offline or no preview</td><td>Verify power, LAN, IP and ADB debugging. Confirm adb devices lists the target. Reconnect, then set up display again.</td></tr><tr><td>Wrong event or role</td><td>Check Server, Event code, Display type and URL preview; press that card’s Set up display.</td></tr><tr><td>Toolbar remains visible</td><td>Check the device model and IP mapping. Wait for loading; rerun setup. If Silk changed after an update, retest the remote sequence.</td></tr><tr><td>Sleep or black screen</td><td>Check setting readbacks, monitor timers, power and HDMI. Distinguish a sleeping stick from a TV that powered off.</td></tr><tr><td>run treats --serial as a build directory</td><td>Use ./run x -s IP:5555 with the existing build; use the modern compatibility wrapper for Homebrew scrcpy.</td></tr><tr><td>scrcpy launcher missing</td><td>Check FTC_SCRCPY_DIR and the executable run file. Setup can continue without scrcpy; inspect Terminal for mirror errors.</td></tr><tr><td>Python 3 not found</td><td>Install Python and ensure its bin directory is in PATH inside the .command file.</td></tr><tr><td>Wrong IP despite reservation</td><td>Verify actual interface MAC and reservation. Do not repeatedly factory-reset; check for a stale reservation or conflicting address.</td></tr></tbody></table><p>Keep the same controller file as the shared operational version. An older single-stick launcher may have different defaults and no seven-device UI. Back up the inventory and the final script before tournament day.</p></section>
