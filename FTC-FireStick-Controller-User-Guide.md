It covers the version with saved startup behavior, automatic reconnect, connection health, location names, group selection and display recovery.</p><nav><a href="#s1">Quick start</a><a href="#s2">The seven devices</a><a href="#s3">Startup behavior</a><a href="#s4">Locations and organizing the page</a><a href="#s5">Assign an event and display role</a><a href="#s6">Group actions</a><a href="#s7">What the individual buttons do</a><a href="#s8">Connection health and previews</a><a href="#s9">Automatic reconnect and restoration</a><a href="#s10">scrcpy windows</a><a href="#s11">Recommended event workflow</a><a href="#s12">What is saved</a><a href="#s13">Troubleshooting</a></nav><section id="s1"><h2>Quick start</h2><ol><li>Power the required TVs and Fire Sticks. Connect the Mac and scoring server to the same event LAN.</li><li>Double-click <strong>FTC-FireStick-Controller.command</strong>. Keep Terminal open; the browser opens the control page.</li><li>Use <strong>Monitor only</strong> when joining an event already in progress. This is the first-run default.</li><li>Restore needed cards from the minimized tray. Minimize unused devices with <strong>−</strong>.</li><li>Enter Server and Event code, choose Display type, and check the device boxes you want to configure.</li><li>Press <strong>Set up selected</strong>, then verify each screen preview shows the correct event and role.</li></ol><p><strong>Before first use:</strong> ADB debugging must be enabled, the Mac must be authorized on every stick, and Python 3, ADB and scrcpy must be installed and configured. The separate Setup Guide covers those prerequisites. This guide covers the updated controller’s operation.</p></section><section id="s2"><h2>The seven devices</h2><table><tr><th>IP address</th><th>Physical model</th><th>Toolbar sequence</th></tr><tr><td>192.168.86.100</td><td>E9L29Y</td><td>E9 sequence</td></tr><tr><td>192.168.86.101</td><td>E9L29Y</td><td>E9 sequence</td></tr><tr><td>192.168.86.102</td><td>E9L29Y</td><td>E9 sequence</td></tr><tr><td>192.168.86.103</td><td>E9L29Y</td><td>E9 sequence</td></tr><tr><td>192.168.86.104</td><td>E9L29Y</td><td>E9 sequence</td></tr><tr><td>192.168.86.105</td><td>K2R2TE</td><td>K2 sequence</td></tr><tr><td>192.168.86.106</td><td>M3N6RA</td><td>E9 sequence</td></tr></table><p>Device .106 has been confirmed working with the E9 menu sequence. Changing it does not immediately run setup.</p><table><tr><th>Choice</th><th>Behavior</th></tr><tr><td>Monitor only</td><td>Connects to visible devices and starts monitoring. Does not send wake, Home, browser-launch or toolbar commands.</td></tr><tr><td>Set up assigned displays</td><td>Runs full setup for each visible device, using its saved assigned URL. Opens no scrcpy windows automatically at startup.</td></tr></table><p><strong>Startup uses visibility, not the group-selection checkboxes.</strong> Minimize a device if you want to exclude it from startup. Each device’s saved assigned URL is used for setup startup; the top event and type selectors do not override it until you press Set up display or Set up selected.</p><p>Startup runs once per controller process. Reloading the browser page does not repeat it. Keep Monitor only for use during matches. If Restore assigned display after reconnect is enabled, subsequent connection recovery can still reopen a page.</p></section><section id="s4"><h2>Locations and organizing the page</h2><p>Type a useful name in the location field on each card, such as <strong>Main Gym Audience</strong>, <strong>Pit Queue</strong>, or <strong>Commons Sponsor</strong>. Click outside the field to save it. New scrcpy windows include the location, IP and model in their title. Already-open windows retain their existing title.</p><p>Click <strong>−</strong> to minimize an unused card. The other cards reflow automatically. Use the tray’s Restore button to bring it back.</p><p>Minimized devices stop receiving preview requests and automatic reconnect checks. They are excluded from startup and group actions. Minimizing does not power off the stick, close its scrcpy window or cancel an action already running. Names and minimized states are saved across restarts.</p></section><section id="s5"><h2>Assign an event and display role</h2><ol><li><strong>Server:</strong> enter the scoring server origin, normally <code>http://192.168.86.37</code>. Use the server’s LAN address, not localhost.</li><li><strong>Event code:</strong> enter the event identifier, initially <code>s0</code>.</li><li><strong>Display type:</strong> choose one of the five choices below. Audience is the default.</li><li>Check the URL preview. For example, <code>http://192.168.86.37/event/s0/display/?type=audience</code>.</li><li>Press the individual card’s <strong>Set up display</strong> or the group’s <strong>Set up selected</strong>.</li></ol><table><tr><th>Choice</th><th>Exact query value</th></tr><tr><td>Audience</td><td>audience</td></tr><tr><td>Field</td><td>field</td></tr><tr><td>Pit</td><td>pit</td></tr><tr><td>Sponsor</td><td>sponsor</td></tr><tr><td>Championship bar</td><td>cmpBar</td></tr></table><p>For different roles, select the audience settings and configure audience devices, then change the type to Pit and configure pit devices. Each successful setup saves that device’s assigned URL. Recovery and setup startup reuse it.</p><p>The top Server, Event code and Display type fields reset to their defaults when a new page opens. The saved assigned URLs remain per device. The current UI does not show the assigned URL on each card.</p></section><section id="s6"><h2>Group actions</h2><p>The checkbox beside an IP selects that device for group actions. A device must be both <strong>checked and visible</strong> to receive a group command.</p><table><tr><th>Control</th><th>Purpose</th></tr><tr><td>Select visible</td><td>Checks every visible card.</td></tr><tr><td>Clear selection</td><td>Unchecks the visible cards. Minimized-device selections are unchanged.</td></tr><tr><td>Set up selected</td><td>Applies the current server, event and display type to the selected devices.</td></tr><tr><td>Reconnect selected</td><td>Retries ADB connections without changing their pages.</td></tr><tr><td>Open selected scrcpy</td><td>Opens continuous mirror/control windows for selected devices.</td></tr><tr><td>Recover selected</td><td>Reopens each selected device’s own saved URL and reruns its toolbar sequence.</td></tr></table><p>Selection checkboxes are saved. A restored card may still be checked from an earlier session, so review the checked boxes before issuing a group action. Individual card buttons work regardless of its selection checkbox. Busy devices reject overlapping actions; check the notice and activity log if a group action skips a device.</p></section><section id="s7"><h2>What the individual buttons do</h2><table><tr><th>Button</th><th>Behavior</th></tr><tr><td>Set up display</td><td>Connects, applies sleep/screensaver settings, wakes the stick, presses Home, opens the chosen URL and hides the toolbar. Saves the URL after completing the display sequence.</td></tr><tr><td>Reconnect</td><td>Connects ADB only. Use when connectivity failed but the correct page is already running.</td></tr><tr><td>Recover display</td><td>Connects, wakes the stick, presses Home, reopens its saved assigned URL and hides the toolbar. Skips sleep/screensaver setting writes.</td></tr><tr><td>Open scrcpy</td><td>Connects and opens a live mirror/control window. Does not run display setup.</td></tr><tr><td>Wake</td><td>Sends the wake key.</td></tr><tr><td>Home</td><td>Leaves the displayed app and opens Fire TV Home.</td></tr><tr><td>Back and Menu</td><td>Send the matching remote keys.</td></tr><tr><td>Arrows and OK</td><td>Navigate the Fire Stick’s current interface.</td></tr></table><p><strong>Recovery uses the saved assignment, not the top selectors.</strong> To change the event or role, use Set up display instead. If no assignment has been saved, recovery uses the initial s0 Audience URL. Visually verify the result; successful commands do not prove that the webpage rendered correctly.</p></section><section id="s8"><h2>Connection health and previews</h2><p>Each card shows its operation status, ADB connection health, last successful screenshot age and activity log.</p><table><tr><th>Indicator</th><th>Meaning and next action</th></tr><tr><td>CONNECTED</td><td>ADB currently reports a device connection. It does not prove the scoring server or webpage is healthy.</td></tr><tr><td>OFFLINE</td><td>No usable ADB connection. Check power, network and reserved IP. Use Reconnect or allow automatic retry.</td></tr><tr><td>UNAUTHORIZED</td><td>Approve the Mac’s debugging prompt on that Fire Stick using the physical remote. The controller cannot approve itself.</td></tr><tr><td>UNKNOWN</td><td>Connection has not yet been established or checked.</td></tr><tr><td>No preview yet</td><td>No successful screenshot has arrived in this controller session.</td></tr><tr><td>STALE</td><td>The last screenshot is older than the freshness threshold. Check the current page and network; an old thumbnail is not proof of a working display.</td></tr><tr><td>Working</td><td>An action is running. Remote and action buttons are temporarily disabled on that card.</td></tr><tr><td>Ready — check preview</td><td>Display commands completed. Confirm the right event, role and hidden toolbar yourself.</td></tr></table><p>Connection checks run about every 10 seconds; the page polls status about every 1.5 seconds. A stale warning appears after the greater of 15 seconds or three times the selected refresh interval. Pausing previews intentionally will eventually make the last image stale.</p><p>Live previews start at <strong>2 seconds</strong>. Choose Realtime, 2s, 5s or 10s. Realtime captures a new screenshot as soon as the previous request finishes; it is not a video stream. For lighter monitoring during a tournament, choose 5s or 10s. Uncheck Live previews to stop automatic capture. Refresh previews updates all visible thumbnails once, regardless of group selection.</p></section><section id="s9"><h2>Automatic reconnect and restoration</h2><p><strong>Auto reconnect every 10s</strong> is enabled by default and saved. It retries offline visible devices, skipping busy and minimized cards. Unauthorized devices require manual approval.</p><p>Each card also has <strong>Restore assigned display after reconnect</strong>, initially unchecked. Enable it on dedicated scoring displays if a lost connection or reboot should reopen the last assigned page after connectivity returns. It can interrupt whatever the stick is currently showing, so leave it off for devices you sometimes use for YouTube or other apps.</p><p>Restoration is intended for a connection lost after the device has connected during the current controller session. A device initially offline in Monitor only mode is first connected without automatically setting up its display. If it returns but still shows Home, use Recover display.</p><p>A page can freeze while ADB remains connected. Automatic reconnect is not a webpage watchdog and will not diagnose that situation. Use a preview, then Recover display if needed. It also cannot remotely repair a missing power supply, changed IP or unapproved ADB authorization.</p></section><section id="s10"><h2>scrcpy windows</h2><p>Open scrcpy during setup is <strong>unchecked</strong> by default. If checked, manual setup opens scrcpy shortly after connecting so you can watch the commands. It does not affect automatic setup at controller startup.</p><p>Mirroring uses a maximum of <strong>800 pixels on the longest dimension</strong>, <strong>15 FPS</strong> and <strong>1 Mbps</strong>. A 16:9 display is approximately 800 × 450 in the mirror. These limits do not reduce the television’s output resolution.</p><p>Use individual Open scrcpy buttons for troubleshooting; opening all mirrors increases load. Closing a mirror does not stop the page on the TV. Minimizing a controller card does not minimize the separate macOS scrcpy window; use that window’s own minimize or close control. Scrcpy errors appear in Terminal.</p></section><section id="s11"><h2>Recommended event workflow</h2><ol><li><strong>Prepare:</strong> check device labels, DHCP reservations, power, server access and ADB authorization.</li><li><strong>Name:</strong> assign location names, then minimize devices not being used.</li><li><strong>Assign:</strong> configure each group’s event and role. Verify all thumbnails and at least the physical displays that matter most.</li><li><strong>Recover:</strong> enable automatic display restoration only on dedicated displays that should always return to their assigned page.</li><li><strong>Monitor:</strong> use Monitor only startup and a 2s–10s preview interval. Open a scrcpy window only when needed.</li><li><strong>During a problem:</strong> inspect the log and health indicator. Reconnect for a connection problem; Recover display for a wrong or stalled page.</li><li><strong>Finish:</strong> close unneeded mirrors, then press Control-C in the controller’s Terminal window. Displays keep running on the sticks.</li></ol><p>Closing only the browser tab leaves the controller process running. Launch one controller instance at a time; multiple instances can compete to send commands. Keep the control Mac awake if continuous monitoring and reconnect are required.</p></section><section id="s12"><h2>What is saved</h2><p>The controller saves these preferences on the Mac: startup mode, automatic reconnect, each device’s location, minimized state, selection checkbox, automatic restoration option and last assigned URL. Location edits save when you leave the field; checkboxes and selectors save when changed.</p><p>Preview interval, Live previews, Open scrcpy during setup and the top server/event/type fields are not persisted. They use defaults when the page is reopened. Activity logs and last-preview timestamps are session-only.</p><p>Preferences are local to this Mac; they do not transfer with the .command file. An advanced operator can override the preference file location with FTC_CONFIG. Keep the controller’s Terminal output available if saving fails.</p></section><section id="s13"><h2>Troubleshooting</h2><table><tr><th>Problem</th><th>First steps</th></tr><tr><td>No control page opens</td><td>Check Terminal for Python or ADB path errors. Confirm the setup guide’s tools are installed.</td></tr><tr><td>One device remains offline</td><td>Check its label/IP, network connection, power and ADB debugging. Restore its card if minimized.</td></tr><tr><td>Unauthorized</td><td>Use the physical remote to allow debugging from this Mac, then reconnect.</td></tr><tr><td>Preview unavailable while connected</td><td>Read the activity log, retry Refresh previews and try scrcpy. Screenshot capture may fail independently of ADB connectivity.</td></tr><tr><td>Wrong event after recovery</td><td>Recovery uses the saved assigned URL. Choose the correct event/type and press Set up display.</td></tr><tr><td>Startup changed but nothing happened</td><td>The setting applies to the next controller launch. Use manual setup now, or stop and relaunch.</td></tr><tr><td>Unchecked device still gets setup at startup</td><td>Startup follows visible devices, not group checkboxes. Minimize it to exclude it.</td></tr><tr><td>Minimized device is not reconnecting</td><td>Restore its card; minimized devices are excluded from automatic reconnect checks.</td></tr><tr><td>Toolbar visible</td><td>Confirm IP/model mapping, then use Recover display. If Silk changed after an update, retest the remote sequence.</td></tr><tr><td>Saved preferences do not appear</td><td>Ensure the same Mac/account and configuration path are used; check Terminal for permission errors.</td></tr></table><p>On new events or after updates, run a preparation test before using the controller during a match. The E9 and M3 use two MENU presses five seconds apart after a five-second page wait. K2 uses its confirmed MENU → DOWN ×5 → MENU → MENU sequence with the configured two-second waits.</p></section></main></body></html>
